## 一、UZI-Skill: 报告生成引擎

### 1.1 模板渲染原理

```python
# assemble.py (瘦身后 587 行)
def assemble(ticker: str) -> Path:
    # 1. 读 raw_data.json, dimensions.json, panel.json, synthesis.json
    # 2. 读 report-template.html (124KB)
    # 3. {{NAME}} {{PRICE}} 等 30+ 占位符替换
    # 4. 22 维数据卡逐一 render_dim_card()
    # 5. 66 评委 panel → render_jury_seat()
    # 6. 插入 SVG 图表
    # 7. 多空辩论渲染
    # 8. 数据质量 Banner
    # 9. 输出 reports/{ticker}_{date}/full-report.html
```

**不依赖任何前端框架** — 100% 后端 Python 字符串拼接：
- SVG 图表：Python 生成 `<svg>...</svg>` 字符串
- HTML 结构：f-string / `.replace("{{VAR}}", val)`
- 模板存储为 `assets/report-template.html`（124KB 单文件）
- 所有 JS/CSS 内联（除了 Google Fonts）

### 1.2 Data Contracts — JSON Schema 契约

一个关键发现：UZI-Skill 用纯文本的 `data-contracts.md`（非 OpenAPI/Swagger）来约定 5 个 Task 之间的 JSON Schema。

```
Task 1 → raw_data.json     (22 维度 × N 字段)
Task 2 → dimensions.json   (19 个维度评分 1-10)
Task 3 → panel.json        (66 评委评分 + 信号)
Task 4 → synthesis.json    (Claude 重写的综合结论)
Task 5 → HTML 报告         (渲染产物)
```

**硬规则**："修改字段名前必须同步更新本文件和 report-template.html。"

重点：`data-contracts.md` 包含了完整 JSON 示例（如 DCF 模型输出、IC memo、Porter 五力分析等），这是给 Claude Code/Codex 读的，不是给人读的——约束 AI 产出的结构。

### 1.3 Quality Checklist — 人机通用的自检清单

```
## 投资者评审
- [ ] 段永平的 comment 必须问到"生意/人/价格"三问之一
- [ ] 章盟主的 comment 必须出现"格局"或"趋势"
- [ ] 北京炒家的 comment 必须谈"首板"或"机构"

## 禁用话术（违反必须重写）
- [ ] 报告中没有："基本面良好"
- [ ] 报告中没有："值得关注"
- [ ] 报告中没有："前景广阔"
- [ ] 报告中没有："建议重视"
- [ ] 报告中没有："存在一定风险"
```

**借鉴点**：quality-checklist 是 LLM 输出质量的最后防线，所有"软性陷阱"都用 checkbox 约束。

### 1.4 多层渲染架构总结

```
┌─────────────────────────────────────────────┐
│          assets/report-template.html         │ ← 124KB 代码模板
│          30+ {{VAR}} 占位符                  │
├─────────────────────────────────────────────┤
│  assemble_report.py (587 行 shell)           │ ← 填充逻辑
│  ├─ render_dim_card(dim_key, score, raw)     │ ← 通用维度卡片渲染
│  ├─ render_dim_category(cat, dims, raw)      │ ← 分类聚合渲染
│  └─ assemble(ticker) → Path                  │ ← 入口
├─────────────────────────────────────────────┤
│  lib/report/ (5 个渲染模块)                   │ ← 拆分组件
│  ├─ svg_primitives.py   — 19 SVG 原语        │
│  ├─ dim_viz.py          — 19 个 _viz_xxx     │
│  ├─ institutional.py    — DCF/LBO/IC 渲染     │
│  ├─ panel_cards.py      — 评委 panel+气泡    │
│  └─ special_cards.py    — 多空辩论+fund      │
└─────────────────────────────────────────────┘
```

## 四、版本管理与发布

### 4.1 UZI-Skill: .version-bump.json — 版本号集中管理

```json
{
  "version": "3.9.1",
  "files": [
    ".claude-plugin/plugin.json",
    ".cursor-plugin/plugin.json",
    "package.json",
    "gemini-extension.json",
    "skills/deep-analysis/SKILL.md",
    ...
  ],
  "patterns": {
    ".claude-plugin/plugin.json": "\"version\": \"VERSION\"",
    "skills/deep-analysis/SKILL.md": "version: VERSION"
  }
}
```

- 所有 version 声明集中在一个文件
- 改版时只改 `version` 字段 + 跑脚本
- 避免漏改某个 SKILL.md 导致版本不一致（详见 issue #73）

### 4.2 daily_stock_analysis: CHANGELOG 扁平化

```
[Unreleased]
- [新功能] 增加飞书静态通知支持
- [改进] 降低大盘分析频率
- [修复] 修复登录超时重定向问题
- [chore] 升级依赖版本
```

**硬规则**：`[Unreleased]` 段使用**扁平格式**，每条独立一行。发版时 maintainer 汇总成带标题的正式格式。目的：减少并发 PR 的 merge 冲突。

### 后两批补充：工具型 Skill / Gateway 数据流

```text
snowball-cli
    public command first
    -> auth command only when needed
    -> JSON output
    -> command provenance for audit

Privora Examples
    public skill-version ping
    -> Bearer token verify
    -> POST /agent/skills/execute {skillId, params}
    -> response shape check
    -> scope / DEK diagnosis

hhxg-market
    static JSON snapshot
    -> schema_version check
    -> cache fallback
    -> Markdown or raw JSON output

quant-buddy-skill
    fresh session
    -> version check
    -> formula execution / SSE resume
    -> TopN sort validation
```

这些项目提醒我们：工具型项目也需要测试策略。测试不一定是完整端到端 UI，而是验证命令输出、response shape、认证边界、缓存提示、版本匹配和错误诊断。

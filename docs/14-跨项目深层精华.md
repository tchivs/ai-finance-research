### 1.2 四层漏斗（industry-funnel）— 最具落地的选股流程

```
第一层：全市场扫描 → 30-60 家（活跃度+涨幅+市值前30并集）
    ↓ 5条硬指标（PE/ROE/现金流/负债率/护城河）
第二层：粗筛 → ≤10 家（全部及格+护城河≥★★★）
    ↓ 精细分析
第三层：精细分析 → ≤10 家（每家300-500字结构化分析）
    ↓ 四大师深度
第四层：终选 3 家（每家800-1200字，巴芒段李四视角）

终选标准：按"投资组合互补性"选（高确定低弹性 + 中等确定中等弹性 + 高弹性高风险）
```

### 1.3 7条去劣硬指标（quality-screen）— 硬性排除

| # | 指标 | 排除条件 |
|---|------|---------|
| 1 | 10年平均ROE | < 8% |
| 2 | 5年累计FCF | 为负 |
| 3 | 利息覆盖倍数 | < 2倍 |
| 4 | 长期毛利率 | < 15% |
| 5 | 经营现金流/净利润 | < 0.7 |
| 6 | 长期净利率 | < 5% |
| 7 | 5年总股本膨胀 | > 20%（非并购） |

**3条豁免规则**：战略投入期、并购整合期、股东回购稀释。

**核心原则**：宁可漏网不可误杀，不错杀任何一流好公司。

### 1.4 供应链瓶颈猎手（bottleneck-hunter）— 最独特的视角

**核心理念**：不问"AI推荐什么股票"，问"如果这个趋势继续扩张，哪一环会先不够用？"

超额收益来源：第一层瓶颈（GPU、HBM、电力）已被充分定价。真正的 alpha 在**第二层、第三层**——光模块、激光器、InP衬底、SOI晶圆、外延设备、晶圆级测试、IC载板、特殊玻纤等。

**趋势筛选标准**：持续性≥3-5年、物理性（需要实际硬件）、规模性（全球Capex>500亿/年）、加速性（需求>供给增速）。

### 1.5 投资论文追踪（thesis-tracker）— 买入后的纪律系统

**核心理念**："买入只是开始。真正的工作是持有期间的持续跟踪。"

**模式A·建立论文**：
- 投资理由（为何买入）
- 估值锚点（安全边界）
- 买入价格
- **关键：卖出条件（巴菲特/李录的做法）**

**模式B·追踪检查**：
- 每季度对照论文检查： thesis 是否完整？
- 财报季检查：承诺追踪（上一季度管理层说了什么，兑现了吗？）

### 1.6 财报精读团队（earnings-team）— 三阶段完整闭环

**阶段一·研究**：四大师并行精读财报
- 段永平：生意变好了还是变差了？
- 巴菲特：赚的是真钱还是假钱？
- 芒格：竞争格局在怎么变？
- 李录：有什么风险信号？

**阶段二·合成**：Team Lead 综合四视角 → 研究报告初稿

**阶段三·发布**：编辑 Agent 改公众号文章 → 读者评审 Agent 提修改意见 → Team Lead 定稿

**资料可得性评级**（A级=完整原文, B级=部分原文/第三方汇总, C级=仅新闻摘要）→ 影响分析深度。

### 1.7 新闻脉搏（news-pulse）— 股价异动快速归因

**4个并行 Agent 侦察**：公司事件、监管政策、行业对手、市场情绪

**输出**：事件时间线 + 异动主因判断 + 是否触发论文重审

**时间窗口**：默认14天，财报季缩到7天。

## 三、daily_stock_analysis：多平台 Bot 架构

之前漏掉了整个 `bot/` 模块——这是**多平台IM接入层**。

### 3.1 命令分发器（bot/dispatcher.py）

```python
class CommandDispatcher:
    ├── RateLimiter（滑动窗口频率限制）
    ├── register/unregister（命令注册注销）
    ├── dispatch（命令分发）
    ├── _try_nl_routing（自然语言路由）
    │   ├── _parse_intent_via_llm（LLM意图解析）
    │   └── _resolve_stock_code_from_text（股票代码解析）
    └── 多平台适配
```

**自然语言路由**：用户不说命令，说"帮我看看茅台最近怎么样"→LLM解析意图→匹配到 analyze 命令。

### 3.2 命令体系（bot/commands/）

```
analyze.py      — 分析单股
ask.py          — 问答（27KB，最大最复杂）
batch.py        — 批量分析
chat.py         — 对话
help.py         — 帮助
history.py      — 历史记录
market.py       — 市场概览
research.py     — 深度研究
status.py       — 系统状态
strategies.py   — 策略管理
```

### 3.3 平台适配（bot/platforms/）

```
base.py            — 抽象基类（每个平台一个文件继承）
dingtalk.py        — 钉钉（Webhook模式）
dingtalk_stream.py — 钉钉（Stream模式）
discord.py         — Discord
feishu_stream.py   — 飞书（Stream模式，24KB最大）
```

**统一接口**：`base.py` 定义 `send()`/`receive()`/`format()`/`parse()`，各平台实现。

## 四、tickflow-stock-panel：应用型量化工作台

tickflow-stock-panel 的独特位置在于：它不是只做采集、只做报告、只做 Agent，也不是直接上复杂交易执行，而是把个人量化最常用的几个动作合成一个自托管工作台。

```text
本地数据湖
    ↓
指标 enriched + 策略信号
    ↓
选股 / 监控 / 回测 / 个股分析 / 大盘复盘
    ↓
React 工作台 + SSE 实时事件
```

### 4.1 三个最可迁移设计

| 设计 | 价值 |
|------|------|
| `CapabilitySet` | 把真实可用能力结构化，业务只读能力，不散落套餐判断 |
| Parquet + DuckDB + Polars | 文件是数据真相，DuckDB 做冷查询，Polars 做热计算 |
| `StrategyDef` | 一份策略定义复用选股、监控、回测，减少口径漂移 |

### 4.2 与 Vibe-Trading 的区别

Vibe-Trading 更像“AI Agent + 交易实验平台”，重点在 MCP、LangGraph、技能生态和多市场回测。tickflow-stock-panel 更像“个人 A 股工作台”，重点在低运维、本地数据、实时行情和可反复操作的页面。

两者不是替代关系：Vibe 适合借鉴 Agent 化与工具暴露；tickflow 适合借鉴自托管应用的产品闭环。

## 五、后两批新增：从大型框架到工具化产品闭环

第五、第六批项目的价值不在“更大”，而在把关键能力收束成可部署、可触发、可审计的小闭环。

| 项目 | 核心定位 | 深层精华 |
|------|---------|---------|
| JCP | 桌面多 Agent 股票会议室 | Moderator 先选专家和任务，再让专家串行讨论，股票记忆参与上下文 |
| PanWatch | TradingAgents 产品化盯盘 | 第三方多 Agent 框架要接入预算、冷却、持仓上下文、提醒和建议池才算产品 |
| Awesome Finance Skills | 金融 skill 集合 | 把 deterministic 工具、Agent judgment、SQLite memory、citation trail 拆清楚 |
| joinquant-skill | 聚宽策略生成与审计 | 平台策略生成必须“模板/参考先行 + AST lint + 因子实验” |
| quant-buddy-skill | 公式执行工具协议 | 工具执行必须防串 session、防旧版本、防错误 TopN、防参数漂移 |
| snowball-cli | 雪球 JSON CLI | 反向接口先 CLI 化，公开接口优先，认证由用户显式执行 |
| hhxg-market | 静态 A 股快照 skill | 盘后数据预计算成 JSON，skill 只负责日期/schema/cache/格式化 |
| Privora Examples | Agent API quickstart | API 示例本身要教最小 scope、response shape、敏感数据 DEK 边界 |
| magpie | 轻量盯盘 daemon | 自选股、提醒规则、冷却、历史、digest 和 synthetic test-fire 构成最小监控闭环 |
| QuantDinger | Agent-ready Trading OS | Agent Gateway 接入策略/回测/订单时，scope、idempotency、audit、paper-only 必须先于智能化 |

这批项目共同说明：金融 Agent 系统不一定每个模块都要重架构。很多高价值能力可以先以 skill、CLI、daemon、static JSON、gateway quickstart 形态落地，只要边界清晰、输出结构化、调用可审计。

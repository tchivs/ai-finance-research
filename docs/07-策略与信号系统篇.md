## 0. 从 Alpha 到组合：PyPortfolioOpt 的确定性分配层

单标的信号、LLM 观点或多因子预测不能直接变成订单。PyPortfolioOpt 将预期收益、协方差、优化目标、权重约束和离散股数分开，适合插在 `StrategyDef` 与 `RebalancePlan` 之间。

```text
SignalRecord / research view
  -> expected return + confidence
  -> covariance / downside risk model
  -> constrained target weights
  -> A-share lot sizing and costs
  -> suggestion pool / paper rebalance
```

### 迁移规则

- 每次优化都保存输入数据版本、频率、风险模型、目标、约束、solver 与失败状态。
- 优先用 long-only、单标的上限、行业上限、最小现金、换手成本做首版；最大 Sharpe、空头和非凸目标不是默认。
- 连续权重与离散订单必须分开审计。PyPortfolioOpt 的离散器默认单股，A 股整手、T+1、停牌、涨跌停和真实费用由本地 adapter 负责。
- Black-Litterman 可把结构化研究观点映射为 `Q/P/omega`，但 Agent 自然语言不能绕过证据、时间范围与置信度转换。

## 1. Vibe-Trading: Signal Engine 引擎模板模式

所有策略遵循统一的 `example_signal_engine.py` 模板：

```python
class SignalEngine:
    def __init__(self, ...):
    def generate(self, data_map: Dict[str, pd.DataFrame]) -> Dict[str, pd.Series]:
        # 输入: {code: OHLCV DataFrame}
        # 输出: {code: signal Series}
```

### 技术基础指标引擎 (technical-basic)

三维度合并 + 投票机制：
- **趋势维度**: EMA/ADX
- **均值回归维度**: 布林带/RSI
- **量价维度**: OBV/量比

```python
def _generate_one(self, df: pd.DataFrame) -> pd.Series:
    votes = pd.Series(0, index=df.index)
    votes += (df['close'] > df['ema20']).astype(int)      # 趋势
    votes += (df['rsi'] < 30).astype(int) * 2              # 均值回归
    votes += (df['obv'] > df['obv'].shift(1)).astype(int) # 量价
    return votes  # 综合得分
```

纯 pandas 实现，适用于任何 OHLCV 数据。

## 3. daily_stock_analysis: YAML 策略声明式定义

16 个策略全部用 YAML 定义：

```yaml
name: dragon_head
display_name: 龙头策略
category: trend
core_rules: [2, 7]
required_tools:
  - get_realtime_quote
  - get_sector_rankings
market_regimes: [sector_hot]
instructions: |
  评估标准：
  1. 板块领涨地位...
  2. 换手率与动能...
  评分调整：
  - 确认为龙头股：sentiment_score +10
```

### 优点
- 非开发者也能添加/修改策略
- `required_tools` → 前置检查可用性
- `market_regimes` → 只在特定市场条件下启用
- `core_rules` → 关联交易理念编号（如理念2=放量确认，理念7=强势趋势股放宽）

### 借鉴点
- HermesAlpha 的策略配置也可 YAML 化
- `market_regimes` 绑定 → 市场状态机 + 策略选择器

## 5. tickflow-stock-panel: StrategyDef 一份定义复用三条路径

tickflow-stock-panel 的策略系统最值得借鉴的点不是内置了多少策略，而是把策略抽成统一的 `StrategyDef`，让同一份定义同时服务：

```text
StrategyDef
    ├── 选股页: StrategyEngine.run()
    ├── 监控规则: MonitorRuleEngine 调用 strategy/signal 条件
    └── 策略回测: BacktestEngine 读取 entry/exit 信号
```

### 策略文件契约

内置策略和用户策略都围绕同一组字段组织：

| 字段/函数 | 用途 |
|------|------|
| `META` | 展示名、分类、描述、风险提示 |
| `BASIC_FILTER` | 市值、价格、成交额、换手等通用前置过滤 |
| `ENTRY_SIGNALS` | 入场信号定义，供选股、监控和回测共享 |
| `EXIT_SIGNALS` | 离场信号定义，回测和监控可用 |
| `filter(df)` | 截面选股，返回命中标的 |
| `filter_history(df)` | 历史窗口信号，供回测批量生成 |

这比“选股一套规则、预警一套规则、回测再写一套”更稳。策略口径改动只需要改一处，下游看到的是同一套信号定义。

### 自研 A 股回测撮合

tickflow 的策略回测主路径已经不是简单信号曲线，而是账户级撮合：

| 约束 | 价值 |
|------|------|
| T+1 | 防止当天买入当天卖出的虚假收益 |
| 涨跌停/停牌 | A 股回测必须处理买不到、卖不出 |
| 单票仓位上限 | 防止小池子策略过度集中 |
| 手续费/滑点 | 把纸面信号拉近真实交易 |
| 按日组合调仓 | 同时支持多标的策略，而不是单票信号验证 |

### AI 策略边界

策略生成可以用 AI，但源码里有 AST 白名单和危险调用拦截。这个边界很重要：AI 只能生成策略定义和过滤函数，不能直接读写文件、发网络请求或触碰业务状态。

### 借鉴点

- HermesAlpha 可以把“扫描、预警、复盘、回测”的规则统一到一份策略契约。
- ashare-audit 的审计规则也可采用 `META + BASIC_FILTER + check()` 的结构，便于解释与记录。
- 回测不要只返回收益曲线，至少要纳入交易约束、成交失败原因和仓位限制。

## 6. QuantDinger: 四向信号 + Agent-ready 策略执行

QuantDinger 的策略系统补上了“Agent 写策略后如何进入真实运行态”的完整链路。它把 AI 生成代码限制在明确契约内，再接入回测、纸面交易、实盘执行和运行监控。

### 指标策略契约

`indicator_workspace.py` 给外部 Agent 暴露 authoring contract，要求新代码输出四列信号：

```text
open_long / close_long / open_short / close_short
```

这比传统 `buy/sell` 更适合同时覆盖现货、合约、多空、开仓和平仓。老 `buy/sell` 仍可兼容，但回测层会显式映射到四向信号并输出 diagnostics。

### strict_mode 回测/实盘对齐

`backtest_execution.py` 把 live `strict_mode` 映射为 backtest execution assumption：严格模式只用已收盘 K 线确认信号，并在下一根 K 线开盘价成交；非严格模式才允许当根或低周期近似撮合。这个边界直接减少回测偷看未来和实盘不可成交的问题。

### 策略生成的安全路径

```text
Agent reads authoring contract
    -> generates Python indicator/script
    -> safe_exec / validator
    -> save indicator or script source
    -> submit backtest job
    -> create/update strategy
    -> paper/live gated execution
```

### 借鉴点

- AI 策略生成必须先拿机器可读 contract，不能只靠 prompt 约束。
- 四向信号列应成为长期策略接口，`buy/sell` 只作为兼容层。
- 回测结果必须写清成交假设：same-bar、next-bar、slippage、warmup、provider range limit。
- 策略进入实盘前应先经过 paper-only 或 suggestion pool，而不是直接连接资金动作。

## 7. ai-berkshire: 动量+价值双轮筛选

### 框架
```
第一层（动量发现）: 60日新高 + 放量确认 → 进入待选池
第二层（价值验证）: 6维评分 ≥ 3/6 → 买入信号
信号分级: 3/6=试探仓3% | 4/6=标准仓5% | 5-6/6=确信仓8%
```

### 6 维评分
| 维度 | 检查内容 |
|------|---------|
| ROE | ROE > 15% 且稳定 |
| 毛利率 | 连续 2 季改善 |
| 营收增速 | 营收同比 > 20% |
| EPS 超预期 | EPS beat > 0% |
| 估值 | PE < 行业均值 |
| 动量 | 60 日新高 |

### stock_screener.py 用法
```bash
python3 stock_screener.py                    # 扫描全部 watchlist
python3 stock_screener.py NVDA TSLA GOOG     # 扫描指定标的
python3 stock_screener.py --update MU        # 更新 MU 基本面数据
```

## 9. 后两批新增：策略不只是一段代码，而是“生成-执行-提醒-解释”全链路

第五、第六批项目把策略系统从“生成信号/回测收益”扩展到更贴近日常使用的链路：平台策略代码生成、公式执行、盯盘提醒、建议池、持仓盈亏和结构化信号。

| 项目 | 策略/信号机制 | 可借鉴点 |
|------|--------------|---------|
| joinquant-skill | 模板优先生成聚宽策略，AST lint 检查未来函数/API 幻觉/交易成本 | 面向特定平台的策略生成必须配套静态审计 |
| quant-buddy-skill | fast_query + 多公式批量执行 + SSE resume + TopN 排序校验 | 公式执行要冻结条件、保留 data_id、验证结果排序 |
| PanWatch | StrategyEngine 管理 suggestion pool，组合建议受权重约束 | AI 建议不能直接等于交易，要进入可审计建议池 |
| magpie | gte/lte/breakout/breakdown alert rules + cooldown | 盯盘规则是最小可用策略单元，也需要历史记录 |
| Awesome Finance Skills | ISQ `InvestmentSignal` + Kronos base forecast + Agent adjusted forecast | 信号要保存强度、置信度、预期差、传导链和来源 |
| Privora Examples | `stock_day` 查询 + portfolio snapshot 本地算盈亏 | 策略/提醒最终要接到持仓和最新价，而不是停在选股 |

### 策略系统的新边界

```text
Strategy idea
    -> platform-specific template or formula
    -> static lint / parameter freeze
    -> execution with provenance
    -> signal object with confidence/source
    -> alert or suggestion pool
    -> portfolio impact / PnL context
```

### 借鉴点

- HermesAlpha 的策略生成要区分：自然语言想法、平台代码、公式条件、回测信号、提醒规则。
- ashare-audit 应检查每个策略产物是否有静态审计、执行参数、结果排序和来源证据。
- AI 输出的“建议”应先进入 suggestion pool 或 paper portfolio，不应直接触发真实交易。

## 10. Lean + PA_Agent：信号、目标、风控和执行不应跨层

Lean 将研究链路分为 `Insight -> PortfolioTarget -> Risk -> Execution`；PA_Agent 则证明在执行前还需要新的价格、账户与风险证据和可过期审批票据。两者共同约束了当前项目的行动链：研究结论既不是目标仓位，也不是订单。

```text
SignalRecord / research view
    -> InsightRecord
    -> TargetWeight / RebalancePlan
    -> deterministic RiskAssessment
    -> ApprovalTicket
    -> PaperOrderIntent
    -> PaperOrder / Fill / reconciliation
```

### 借鉴点

- `InsightRecord` 必须包含数据截止时间、策略/模型版本、方向、周期、置信度和来源证据；自然语言报告只是它的渲染结果。
- 组合层输出连续目标权重；A 股整手、T+1、停牌、涨跌停和费用在离散化/市场 adapter 层处理。
- 风控可以减仓、归零或拒绝计划，不能只在 UI 展示 warning。
- 只有批准后的 paper intent 能进入执行器；订单受理、拒绝、部分成交、完全成交和取消是不同的持久化事实。

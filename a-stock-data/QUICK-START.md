# a-stock-data 快速概览

> A 股全栈数据 Skill · 10 层架构 · 40 个端点 · 13 个数据源 · 零第三方数据封装依赖
> 源码: `/root/source/tmp/a-stock-data/`
> 原始仓库: <https://github.com/simonlin1212/a-stock-data>

---

## 一句话定位

`a-stock-data` 是一个把 A 股公开数据源封装成 Agent 可直接调用的单文件 Skill。它不追求工作台 UI，也不做复杂多 Agent，而是把行情、研报、资金流、龙虎榜、解禁、财务、公告、涨停池、ETF 期权、互动易问答等底层数据能力整理成可复制、可执行、可被 AI 理解的工具层。

它最值得学习的点是数据源优先级和失效治理：能用 mootdx/腾讯就不用东财，东财只拿独有数据且所有请求统一走 `em_get()` 限流。对当前项目来说，它是比 akshare 封装更接近底层真相的 A 股数据蓝图。

## 最高价值借鉴点

| 借鉴点 | 位置 | 可复用价值 |
|---|---|---|
| 数据源优先级 | `README.md`, `SKILL.md` | 按封 IP 风险和独有能力排序，而不是“哪个库方便用哪个” |
| 东财统一限流 | `SKILL.md` 的 `em_get()` | 所有 Eastmoney 调用串行、抖动、复用 session、连接重试 |
| 直连 HTTP/TCP | `SKILL.md` 各端点代码块 | 移除 akshare 这类中间封装，降低版本和字段漂移风险 |
| 十层数据分类 | `README.md` 架构图 | 把行情、研报、信号、资金面、新闻、基础数据、公告、打板、期权、舆情分层 |
| 端点级踩坑记录 | `README.md` 更新日志 | 每个失效接口、字段误判、参数 bug 都写成可迁移经验 |
| 互动易/热榜/人气榜 | 舆情互动层 | 补“公司如何回应传闻”和“市场把票归到什么概念” |
| 打板情绪层 | 涨停池/炸板/跌停/昨涨停 | 短线情绪指标可直接服务盘后复盘和监控 |
| ETF 期权层 | 新浪 T 型报价/Greeks/IV | 期权数据可作为情绪和波动率侧证，不必本地算 BSM |

## 数据源优先级原则

| 优先级 | 数据源 | 风险 | 用途 |
|---|---|---|---|
| 1 | mootdx/通达信 | 不封 IP，但海外 TCP 可能超时 | K 线、盘口、逐笔、财务快照、F10 |
| 2 | 腾讯财经 | 不封 IP | 实时价、PE/PB、市值、换手、涨跌停、指数、ETF |
| 3 | 同花顺/新浪/巨潮/百度 | 低 | 热点、北向、财报、公告、K 线均线 |
| 4 | iwencai | 需 Key | 自然语言跨主题研报/字段检索 |
| 5 | 东财 | 有风控 | 龙虎榜、解禁、两融、大宗、股东户数、分红、研报、新闻、资金流 |

迁移原则：当前项目可以把这个排序写成 `ProviderPolicy`，所有采集任务先问“这个字段是不是东财独有”。不是独有就不要默认走东财。

---

## 最适合迁移的模块

1. **Provider Policy**: 给每类字段定义首选源、备选源、限流策略和失效说明。
2. **Eastmoney Client**: 做一个共享 `em_get()`，禁止业务代码裸调东财。
3. **Ticker Normalize**: 所有输入统一支持 `688017`, `SH688017`, `688017.SH` 等格式。
4. **Data Source Notes**: 每个端点记录字段单位、已知失效、风控行为、验证日期。
5. **Limit-up Sentiment**: 将涨停池、炸板率、连板梯队纳入市场复盘。
6. **Investor Q&A Context**: 互动易回答适合进入个股事件解释和风险核验。

## 注意事项

- mootdx 适合国内网络，海外环境可能 TCP 7709 超时，需要代理或替代源。
- mootdx `bars()` 参数名是 `frequency`，写成 `category` 会静默退化成日线。
- mootdx 返回不复权原始价，跨除权日回测必须自行复权或改用前复权源。
- 腾讯字段 43 是振幅，不是 PB；PB 在字段 46。
- 东财资金流单位是元，不能默认当万元。
- 互动易、热榜、人气榜是舆情证据，不是投资结论。
